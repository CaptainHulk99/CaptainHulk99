### `>_` about me

I work incident tickets end to end: triage the alert, baseline what "normal" looks like for the account, hunt for how the attacker actually got in, check what they did once inside, scope who else was hit, then write it up so someone non-technical can act on it. I like KQL, I like log data that tells a story if you ask it the right questions, and I like catching the thing that looks almost like a false positive but isn't.

Currently building out simulated SOC engagements to sharpen investigation and reporting skills before stepping into the role for real.

### `>_` how I work an incident

```
1. Triage      → is the alert real, or explainable?
2. Baseline    → what does normal look like for this account?
3. Attribution → how did they actually get in?
4. Persistence → what did they leave behind?
5. Scope       → who else got hit? never assume one victim.
6. Contain     → revoke, reset, remove persistence, block infra, verify.
7. Report      → write it so a non-technical exec understands it in 60 seconds.
```
